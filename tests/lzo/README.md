# LZO pilot vectors

`vectors/` holds 286 synthetic LZO1X streams plus `manifest.json` and `cases.tsv`
(the same cases, tab-separated, which the tests read), generated by
`gen_vectors.c` with liblzo2 (regenerate: `./build/lzo_gen_vectors tests/lzo/vectors`).

Each case: `file` (input), `dst_capacity`, `valid`, and the expected
`expect_ret`, `expect_out_len` and `expect_out_fnv64` (FNV-1a 64 of the bytes written).

- **Valid** cases (`lzo1x_1`, `lzo1x_999`): the result is defined by the LZO1X format,
  so the game's LZO 2.01 code must match exactly.
- **Damaged** cases (`truncated_*`, `corrupted`, `trailing_bytes`, `dst_too_small`):
  expected values come from liblzo2 2.10. LZO 2.01 may differ on these; the
  authoritative answer is the original x86 fixture run in an emulator.

## Tests

- `lzo_oracle` (needs Unicorn): runs the original x86 `lzo1x_decompress_safe` fixture
  on every case. All 166 valid cases match liblzo2 exactly. 17 of 120 damaged cases
  differ from liblzo2 2.10 (LZO 2.01 reports `-7` "EOF not found" on several truncated
  streams where 2.10 reports `-4`, and counts the bytes it wrote before failing).
  Its results are saved as `vectors/oracle-lzo2.01.tsv` (columns: id, ret, out_len,
  out_fnv64, guard_ok, regs_ok).
- `lzo_recomp`: runs the recompiled function on every case and requires results
  identical to `oracle-lzo2.01.tsv`, including untouched guard bytes after the output
  buffer and restored callee-saved registers. Needs no emulator.

Both use the guest memory layout defined in `lzo_cases.h`.
